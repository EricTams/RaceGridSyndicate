# Architecture

The game lives in `game/` as a static site: `index.html`, one stylesheet and plain JavaScript files. There is no build step, so the folder can be served as-is locally (`./play.sh`) or from GitHub Pages.

## Layout

| Folder | What lives there |
| --- | --- |
| `game/css/` | `game.css`, all page styles |
| `game/js/core/` | Small shared helpers (`$`, `mod`, `rand`) |
| `game/js/data/` | Tuning constants and data: orders, parts, regulations, drivers, abilities, compounds, teams |
| `game/js/render/` | Three.js materials, camera, effects pools, per-frame visuals, views, labels and HUD; `showcase.js`, your car turning on a display stand in the office screens where the car is built (its own small canvas and renderer, drawn only while its screen is open: the race canvas is hidden behind office screens and must never be drawn into) |
| `game/js/world/` | Building the scene: `circuit.js` (`loadTrack(def)` rebuilds the circuit, pit lane, city hints and landmark for each race from `data/tracks.js`), cars; team and league state |
| `game/js/sim/` | The race simulation (reset, combat, strategy, per-tick step), qualifying, driver morale and raises, sponsors and the team championship, events, the Fixer's calls (`fixer.js`), the Backer, staff, HQ rooms, and the season between races |
| `game/js/tune/` | The Night Tune (its flying laps are the qualifying runs) |
| `game/js/ui/` | Driver cards, timing tower, garage screen (tabs), sponsor, staff and Backer screens, the career summary, controls and layout |
| `game/js/audio/` | Music and sound effects with Web Audio. `synth.js` holds the voices, the effects and the mixer: music and SFX have separate volumes, and the music ducks under big effects. `sequencer.js` plays a song in a style. `styles.js` has the Darksynth variants and Chill. `songs/` holds public-domain scores converted by `tools/midi2song.mjs` (sources in `assets/music/src/SOURCES.md`). `sfx.js` is the sound effects: `sfx(id, {car})`, which rate-limits each sound, a synth recipe per sound, and recorded samples from `game/sfx/` for the physical ones. `director.js` picks the song and style for the screen and runs the SOUND volume popover and the M mute key. Audition at `game/?music` and `game/?sfx` |
| `game/sfx/` | Recorded sound effects (22 kHz mono WAV), built from CC0 sources in `assets/sfx/src/` by `node tools/sfx-build.mjs`. The recipes are in that script, and credits are in `assets/sfx/SOURCES.md`. `--scan` lists where each source's sounds sit |
| `game/js/main.js` | Boot and the main loop |

**A new career** opens with the credits (`ui/credits.js`; the music, track and map lines there are required by their licenses, see `CREDITS.md`), then the crew (`sim/staff.js`, `ui/staff.js`), the drivers (`sim/draft.js`, `ui/draft.js`), the first car and its design meeting (`sim/newcar.js`, `ui/newcar.js`), then sponsors and the Backer. At every season end `nextRace()` builds everyone's new car (`measureCarry` before promotion, `buildNewCars` after). **The weekend flow:** at a season start, sponsors → staff → Backer (each skipped when there's nothing to decide); then the track preview (`ui/preview.js`, the circuit on the race view before any tuning) → the Night Tune team baseline → qualifying, with tune 2 and the final tune in the box between runs → grid screen → race → garage → next race. Season changes happen in `nextRace()` (`sim/season.js`).

## How the scripts fit together

- Each file is a plain `<script>` (not an ES module). All files share one global scope, so a `const` or `function` declared in one file is visible to every file loaded after it.
- **Load order matters** for code that runs when a file loads (building the scene, creating cars). The order in `game/index.html` is the dependency order; add new files where their dependencies are already loaded. For example `sim/morale.js` loads before `world/cars.js` because creating the cars calls `initDriverCareer`.
- Code that only runs later (functions called from the main loop or from buttons) can reference anything, whatever the file order.
- `three.js` r128 comes from cdnjs as the global `THREE`.
- **Free what you remove from the 3D scene.** `scene.remove()` alone leaves geometries, materials and textures on the GPU; call `disposeTree(obj)` (`core/util.js`) too. Loading a new track every race without it leaked a whole city per race until Chrome lost the WebGL context (white races).

## Testing and debugging

- Everything is reachable from the browser console: `cars`, `race`, `league`, `TEAMS`, `stepSim(dt)`, `updatePanels()`, `render(dt, t)` and so on. A whole race can be run instantly with a loop over `stepSim`.
- Balance simulations live in `sim/` (Python): `night_tune_sim.py`, `season_econ_sim.py`, `career_sim.py`.
- Ability lab: `node tools/headless-shot.mjs out.png "$(cat tools/ability-lab.js)"` runs a seeded solo time trial on every track with a neutral driver, with and without each track ability, and prints the % of lap time each one saves.
- Crew lab: `node tools/headless-shot.mjs out.png "$(cat tools/crew-lab.js)"` measures what each staff skill does: each role's two skills in a 2×2 (neither, A only, B only, both), with and without the other. Season mode (default) plays two whole Gutter Circuit seasons with the game's own code (Night Tune, qualifying, race, `settleRace()`, sponsors, payroll, `measureCarry()`/`buildNewCars()`) on a real grid: each slot is a team as a career start makes it (its seed's car, cash, manager, reputation, drivers, and a crew hired by the real AI hiring), and the variants rotate through every slot over groups of 4 runs so slot differences cancel. It holds promotion, staff and driver turnover and aging still, and leaves out your-team-only systems (events, the Backer, HQ, the market). `window.CREW_LAB={roles:['chief'],reps:10,seasons:2,grid:'real'|'flat',mode:'season'|'race'}` sets it up. Its GRID lines are the grid's averages per team per season, to compare with `tools/grid-reference.js`, which records the same numbers for the real AI teams in an autoplay career: `node tools/headless-shot.mjs out.png "$(cat tools/grid-reference.js)" "autoplay=1&seasons=2&wait=4"`. Season 1 matches the real grid on every measure; season 2 runs a little richer in car level and morale and poorer in cash, because the real grid's promotion and relegation are held still.
- Track tools in `sim/`: `track_metrics.py` measures circuits (corners by type, chicanes, straight share, direction) for real outlines and our tracks alike; `build_tracks.py` turns real circuit outlines into game tracks (paste its output into `data/tracks.js`).
- Autoplay plays whole careers with a manager policy: open `game/?autoplay=3&laps=4` (add `&short` for 4-race seasons). The report appears on screen. `node tools/headless-autoplay.mjs "autoplay=3&laps=4"` runs it in headless Chrome and prints the report, which is handy for long balance runs. `&skill=poor|fine|amazing|perfect` sets how well the manager plays (default fine) and `&seasons=N` stops each career after N seasons; the report then lists the season-1 finishes. `RGS_GPU=1` makes it render on the real GPU (Metal) instead of the software renderer and report WebGL context losses. `RGS_URL=http://localhost:8001/game/` points the headless runner at another copy of the game, so a long run can use a frozen snapshot while you keep editing.
- The track viewer flips through every circuit in the full-track view: open `game/?tracks` (one second each, or `?tracks=3` for three; add `&only=london,chicago` for just those tracks; add `&drive` or `&drive=N` to race the field live on each track and move on once the leader has done N laps). Left/right step, space pauses. `tools/freeway-check.js` measures the freeway checklist (`docs/FREEWAY_CHECKLIST.md`) per track. `tools/water-check.js` counts each track's separate bodies of water (a landmark pad or sketch shape that cuts a bay off from its channel shows up as an extra one). `tools/fit-check.js` reports how much the scenery squeezes each circuit in the full-track view (100% = framed as if alone) and what widens each side; freeway junctions may widen the view by at most 12% a side, so a landmark set too far out is what shrinks a track. `tools/turn-track.js` (run with `?bake`) previews one track turned to several angles in its city, with how big it shows and how much the scenery squeezes it; a chosen angle is applied once to the ctrl points in `tracks.js` (noted as `turned:`), never at load. Geo-placed cities (Vegas onwards) are built from real coordinates: `tools/osm-geo.mjs <s,w,n,e> geo.json` fetches a box's water (lakes, rivers, canals, sea coast) and motorways from OpenStreetMap; `tools/geo-fit.mjs <id> geo.json --near lat,lon --along lat,lon:lat,lon` searches where the circuit sits (position, map scale, turn) on land and clear of the freeways, with a chosen direction along the wide screen (`--deg` limits the turn, e.g. to put the water behind the circuit); `tools/geo-place.mjs <id> '<placement>' geo.json [road names]` prints the sketch entries (`{poly}`, `{road}`) for that placement, or turns named lat,lon points into frame units for landmarks. A track built from its own city's circuit (Las Vegas) is placed by giving the circuit's name instead of a placement (the real outline in `sim/f1-circuits.geojson` is fitted onto the ctrl points). Shared helpers are in `tools/geo-lib.mjs`; geo-placed sketches pin `{turn:0}`. `tools/topdown-map.js` draws a plain north-up plan of one track (water, land, circuit, freeways, landmark), for checking geography the isometric view hides. `tools/kink-check.js` (run with `tools/headless-shot.mjs`) checks every track for road edges that fold or spike, and for stretches of road that overlap another (closer than a road width; the builder's close-pass nudge skips anything within about 33 units along the lap, so a hairpin's two legs can overlap). Set `window.KINK_TRACKS=[defs]` first to check just those, e.g. while trying control-point edits.
- **Scenery placements are baked.** Each track's water sketch turn, landmark spot and finished freeways are saved in `game/js/data/scenery.js`, and the game loads those instead of searching. After changing a placement rule, a water sketch or a freeway style, re-bake: `node tools/bake-scenery.mjs` (every unlocked track) or `node tools/bake-scenery.mjs sydney london` (just those; add `--force` for locked ones). Mark a track `locked:true` in `scenery.js` once you're happy with it and re-bakes leave it alone; values can be edited by hand. Every sketched city pins its map orientation with `{turn:k}` in `waters.js`: a re-bake re-runs the search, and an unpinned turn can flip the whole map (water, landmark, freeways) after a small sketch edit. Open the game with `?bake` to see the live search instead of the saved result.

## Frozen prototypes

`prototypes/` holds earlier experiments (`Sprite Forge.html`, `drone-feed.html`). They are kept for reference and are not updated; new work goes in `game/`.

## Likely next step

When the race logic needs to run headless (automated tests, sharing code with the balance sims), move to ES modules and separate simulation state from Three.js objects. Today the car objects mix both (`c.pos`, `c.root`, material uniforms).
